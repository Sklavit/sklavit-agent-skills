# Medium & Extended Blog Post Templates

## Medium vs LinkedIn: Key Differences

| Aspect | LinkedIn Post | Medium Article |
|--------|--------------|----------------|
| Length | 250-300 words | 1000-2500+ words |
| Depth | High-level insights | Deep technical explanations |
| Structure | Casual, scannable | Formal sections with headers |
| Code | Brief snippets only | Full code examples with context |
| Purpose | Spark discussion | Comprehensive tutorial/guide |
| Visuals | Optional | Cover image required, diagrams encouraged |

## Medium Post Structure

### Essential Components

1. **Cover Image** (Required)
   - High-quality, relevant image
   - Represents the article content
   - Can use free resources: Unsplash, Pexels

2. **Title** (Critical)
   - Clear and specific
   - Includes main keyword
   - 6-12 words optimal
   - Promises value

3. **Subtitle** (Important)
   - Expands on title
   - Sets expectations
   - 1-2 sentences

4. **Introduction** (Hook readers in first 100 words)
   - Context: Why this matters
   - Problem: What issue you're solving
   - Promise: What readers will learn
   - Credibility: Brief credentials if relevant

5. **Body** (Main content)
   - Clear sections with H2/H3 headers
   - Logical flow
   - Examples and code snippets
   - Visual breaks (images, diagrams, code blocks)

6. **Conclusion**
   - Summarize key takeaways
   - Next steps or call-to-action
   - Link to related resources

## Writing Best Practices for Medium

### Opening Hook Strategies
1. **Start with the result:** "Our database query time dropped from 3 seconds to 30ms."
2. **Start with the problem:** "We were losing $50K/month to a single database query."
3. **Start with a question:** "What if I told you most caching strategies are backwards?"
4. **Start with a statement:** "In 2024, we rewrote our entire backend. Here's what we learned."

### Maintaining Flow
- Use transitions between sections
- Each section should logically lead to the next
- Use "Now that we understand X, let's look at Y" type transitions
- Avoid jarring topic switches

### Code Best Practices
- Always include comments in code
- Explain why, not just what
- Show before/after when demonstrating improvements
- Use syntax highlighting
- Keep code blocks digestible (10-30 lines)

### Visual Elements
- Diagrams for architecture/flow
- Screenshots for UI/results
- Graphs for metrics/benchmarks
- Tables for comparisons
- Code blocks with syntax highlighting

### Voice and Tone
- Professional but conversational
- Use "we" and "I" (personal experience)
- Admit mistakes and limitations
- Show, don't just tell
- Be specific: Use real numbers and examples

### Technical Depth
- Define acronyms on first use
- Explain concepts before using them
- Layer complexity: simple → detailed
- Provide context for decisions
- Include links to deeper resources

## SEO and Discoverability

### Title Optimization
- Include main keyword
- Be specific, not generic
- Use numbers when applicable: "5 Ways to..." "From 10s to 100ms"
- Promise value: "How to", "A Guide to", "Understanding"

### Content Structure for SEO
- Use H2 and H3 headers with keywords
- Include internal links to related posts
- Add alt text to images
- Use descriptive code block titles
- Include a meta description (first paragraph)

### Tags on Medium
Choose 5 tags:
- 1-2 broad (e.g., "Software Development")
- 2-3 specific (e.g., "Redis", "Database Optimization")
- 1 audience-focused (e.g., "Startup Engineering")

## Publishing Strategy

### Before Publishing
- [ ] Proofread for typos and grammar
- [ ] Check all code for syntax errors
- [ ] Verify all links work
- [ ] Ensure images load and have alt text
- [ ] Review on mobile preview
- [ ] Get feedback from 1-2 technical reviewers

### After Publishing
- Share on LinkedIn with a shorter summary
- Post in relevant Reddit communities (with care not to spam)
- Share in Slack/Discord communities you're part of
- Consider email newsletter if you have one
- Engage with comments and questions

### Extending LinkedIn Posts to Medium

When expanding a LinkedIn post into a Medium article:

1. **Expand the hook** → Full introduction with context
2. **Elaborate each point** → Dedicated sections with details
3. **Add technical depth** → Code examples, architecture diagrams
4. **Include implementation** → Step-by-step how-to
5. **Address edge cases** → Common problems and solutions
6. **Add resources** → Further reading, tools, repos
7. **Provide context** → Industry landscape, alternatives

**Example:**

LinkedIn post (280 words):
```
Hook: "We cut API latency from 2s to 80ms"
Problem: REST API for real-time data
Solution: 4 bullet points
Result: metrics
CTA: "Have you had similar moments?"
```

Medium article (1800 words):
```
- Introduction (200w): Full context, why it matters, what readers learn
- Background (300w): System architecture, scale, traffic patterns
- The Problem (400w): Detailed diagnosis, metrics, user impact
- Investigation (300w): How we identified the root cause
- The Solution (500w): Step-by-step implementation with code
- Results (200w): Comprehensive before/after metrics
- Lessons Learned (200w): Generalizable insights
- Resources (100w): Tools, further reading
```

## Final Checklist for Medium Posts

### Content Quality
- [ ] Clear, specific title
- [ ] Engaging opening (hooks reader in 30 seconds)
- [ ] Logical structure with descriptive headers
- [ ] Practical code examples with comments
- [ ] Visual elements (diagrams, screenshots, graphs)
- [ ] Real metrics and specific outcomes
- [ ] Honest about trade-offs and limitations
- [ ] Clear takeaways and next steps

### Technical Accuracy
- [ ] All code tested and runs
- [ ] Technical claims verified
- [ ] Links to authoritative sources
- [ ] Alternatives/edge cases acknowledged

### Readability
- [ ] Short paragraphs (2-4 sentences)
- [ ] Varied sentence length
- [ ] Active voice primarily
- [ ] Clear transitions
- [ ] Scannable (headers, bullets, bold text)

### Professional Polish
- [ ] No spelling/grammar errors
- [ ] Consistent terminology
- [ ] Proper formatting (code blocks, headers)
- [ ] Cover image included
- [ ] Author bio included
